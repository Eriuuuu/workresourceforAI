两阶段工作流引擎

集成广联达 Copilot 工作流平台，异步提交 + 轮询等待

阶段 1 需求点生成

  • 输入：需求文档内容 + 已提取实体字符串
  • 调用广联达工作流 ff1d44be...
  • LLM 将需求拆解为多组需求堆栈
  • 输出：requirement_stacks（分堆）+ requirement_doc
  • 轮询机制：最多 1000 次 x 10s 间隔

阶段 2 测试用例生成

  • 输入：每个 stack 中的每条 requirement
  • 调用广联达工作流 14d28af1...
  • 逐一为每条需求生成完整测试用例
  • 输出：标准格式用例（ID/名称/步骤/优先级）
  • 支持直接 dict 或 URL 下载两种响应模式

关键技术细节

异步提交：后台线程执行，前端轮询获取结果

安全取值：自动判断节点输出是 dict 还是 URL

JSON 提取：正则提取 [...] JSON 数组

优先级映射：High → 高, P0 → 高, P2 → 中等

知识库构建

C++ 代码库 → 向量索引 + 图谱索引，双通道存储

向量通道 ChromaDB

  • 文档加载：LangChain TextLoader + 编码容错（UTF-8 → latin-1）
  • 智能分割：RecursiveCharacterTextSplitter，优先在 class/struct/namespace 边界分割
  • 参数：chunk_size=2000, overlap=200
  • 嵌入：bge-m3（1024维），批量5条 + 3次重试 + 指数退避
  • 元数据：file_path, content_hash, total_lines, file_size, chunk_id
  • 检索：similarity_search_with_score，L2 距离 < 2.0

图通道 Neo4j

  • 解析器：libclang AST → 正则 → 简单正则（三级降级）
  • 实体：Function / Class / Struct / Namespace / Enum / Constructor / Destructor
  • 关系：CONTAINS（包含）+ CALLS（调用）
  • 复合主键：qualified_name = namespace::parent::name@file_path
  • 调用推断：基于函数签名中的名称引用匹配
  • 索引：按 file_path + name 双索引，全文搜索支持

混合检索系统

三阶段检索：语义搜索 + 结构搜索 + 合并去重

阶段 1 语义检索

  • 向量相似度搜索 (k=20)
  • L2 距离 < 2.0 过滤
  • 转换为 0~1 置信度分数
  • 保留前 15 个 chunk

阶段 2 结构检索

  • 实体精确匹配 (5类)
  • CONTAINS/CALLS 关系扩展
  • 关键词模糊搜索（不区分大小写）
  • 中英文同义词扩展（60+组）
  • 结构关键词向量补充

阶段 3 合并去重

  • chunk 级 + 实体级去重
  • 按分数排序
  • 读取完整文件内容
  • 附带实体摘要信息

中英文同义词系统（示例）

导出 ↔ Export

初始化 ↔ Init / Initialize

函数 ↔ Function / Method

类 ↔ Class / Struct

删除 ↔ Delete / Remove

创建 ↔ Create / New

调用 ↔ Call / Invoke

实现 ↔ Implement / Override

多轮自适应 RAG 问答

不是固定检索一次，而是由 LLM 判断是否需要更多信息

→

排除已检索文件
→
生成回答
基于全部检索结果

LLM 评估维度

  • is_sufficient：信息是否充分
  • analysis：分析当前已有信息的覆盖度
  • search_direction：如果不足，下一轮该搜索什么
  • 温度 0.1，确保决策稳定性

核心机制

  • 文件去重：跨轮次 exclude_files 排除已检索
  • 提前终止：无新增文件且无检索方向时停止
  • 最多 3 轮：强制上限保证响应时间
  • 进度推送：每轮状态实时推送到前端
